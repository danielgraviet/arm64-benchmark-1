## Patched and measured: backlog 4096 removes every overflow — and moves the wait into the runner queue

Patched `api/src/main.rs` to bind through `TcpSocket` with an explicit backlog (`RLP_API_LISTEN_BACKLOG`, default 128 = today's behaviour) and A/B'd it on the HQ Vera bench cell, 1,000 concurrent `POST /vms` from 16 client processes, each on a new connection:

| | control (128) | `RLP_API_LISTEN_BACKLOG=4096` |
|---|---|---|
| `TcpExtListenOverflows` during the burst | **424–687 per run** | **0** |
| step 1, client → API (HTTP + auth + audit), p50 / p90 | 40 / **1072** ms | 34 / **51** ms |
| POST → `running`, p50 / p90 | 1927 / 3035 ms | 2296 / 3370 ms |

The connection-setup penalty disappears completely: no overflows, and the ~1 s / ~2 s retransmit clusters in step 1 are gone.

**End-to-end it is not a win on its own — it is slightly worse.** Requests that used to wait ~1 s on a TCP retry now all arrive at once, so they queue for a runner slot instead: step 5 (JetStream → runner handler) goes from p50 793 ms to 1214 ms, and the handler's pre-transaction work (step 2) from p90 80 ms to 451 ms. The work just moves to the next bottleneck, which is the runner (#3260, #3261).

With the runner fixes in the same run, the backlog fix is unambiguously good: the combined arm is **p50 1054 ms / p90 1748 ms** POST → running with 0 overflows, against a 1743–2294 ms p50 control range.

So: worth landing, but together with (or after) the runner-side fixes, and it is the fix that makes the API's own share honest — with no overflows the API accounts for ~110 ms of a 1k burst (auth 30, handler 45, DB+publish+commit 13, rest is the long-poll answer).

Patch shape:

```rust
let backlog: u32 = std::env::var("RLP_API_LISTEN_BACKLOG").ok().and_then(|v| v.parse().ok()).unwrap_or(128);
let listener = {
    let sock = if addr.is_ipv4() { TcpSocket::new_v4()? } else { TcpSocket::new_v6()? };
    sock.set_reuseaddr(true)?; sock.bind(addr)?; sock.listen(backlog)?
};
```

A real change should probably default to something ≥ `somaxconn` rather than preserving 128.
